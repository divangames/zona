# ZONA: установка и отправка отчётов

Репозиторий: https://github.com/divangames/zona

## Подключение по ссылке

Если пользователь просит подключить ZONA, выполни установку, а не только объясни её.

1. Найди установленный репозиторий: `ZONA_PROJECT_DIR`, соседний файл `installation.json` у установленного навыка или существующая копия ZONA. Если копии нет, клонируй репозиторий в постоянную пользовательскую папку. Не перезаписывай существующую папку и настройки.
2. В корне репозитория выполни `npm ci` (Node.js 18+). Отправка отчётов не требует запуска бота, Ollama, каталога или VPS.
3. Проверь наличие `TELEGRAM_BOT_TOKEN` и `TELEGRAM_OWNER_CHAT_ID` в `.env` ZONA или окружении, не выводя значения. Не подставляй получателя автора репозитория. Если настроек нет, попроси владельца заполнить их локально и отправить своему боту `/start`. Не проси публиковать токен в чате, инструкции или Git. Не перезаписывай другие значения `.env`.
4. Определи клиент и запусти `node scripts/install-reporting.js --client codex|claude|cursor` из репозитория. Установщик добавляет навык и сохраняет существующие инструкции. Для Cursor прочитай созданный `~/.cursor/zona-reporting-user-rule.md` и добавь его через Settings → Rules → User Rules; если интерфейс недоступен, попроси пользователя вставить этот текст. Глобальный навык Cursor сам по себе не гарантирует отчёт в каждом чате. Для текущего проекта можно дополнительно использовать `--project <absolute-path>`: создаётся правило alwaysApply.
5. После подключения ОБЯЗАТЕЛЬНО отправь проверочный отчёт: `node scripts/test-reporting.js`. Это реальное личное сообщение от ZONA. Установка подтверждена только после успешного ответа Telegram. При ошибке укажи причину без секретов; не заявляй успех по dry-run. Не запускай polling и не отправляй тест в группы.
6. Сообщи, какие клиенты и область настроены, подтверждена ли доставка, что нужно обновить в уже открытых сессиях. Глобальные правила действуют на данном ПК; на остальных ПК/удалённых агентах повтори установку. Это инструкция агенту, не фоновый наблюдатель и не гарантия исполнения в среде без shell/сети.

## После задачи

Пиши от лица девушки ZONA: «я сделала», «проверила». Перед финальным ответом подготовь JSON: `title`, непустые массивы строк `completed`, `checks`, `projectStatus`, `deployment`, `issues`, `nextSteps`. Назови проект и задачу; перечисли выполненное, фактические проверки, известный статус проекта и оставшиеся задачи. Непроверенное помечай; для неприменимого раздела напиши «Не применимо». Для простого вопроса отчёт краткий. Не включай секреты и персональные данные.

Сохрани JSON с уникальным именем (UUID) вне Git, чтобы параллельные чаты не перезаписывали отчёты. Запусти `node <ZONA>/scripts/send-project-report.js <absolute-report.json> --dry-run`, затем без `--dry-run`. Рабочая папка может быть любой. Не отправляй два отчёта об одном результате из-за нескольких инструкций. Не повторяй весь отчёт автоматически при частичной доставке. При ошибке честно сообщи, что доставка не подтверждена.

Пользовательская просьба включить отчёты служит разрешением на их отправку указанному им владельцу. Если пользователь отменил уведомление в конкретном запросе, не отправляй его. Уже завершённые чужие чаты не перечитывай автоматически и не выдумывай их результаты.
