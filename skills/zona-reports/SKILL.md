# ZONA: установка и отправка отчётов

Репозиторий: https://github.com/divangames/zona

## Подключение по ссылке

Если пользователь просит подключить ZONA, выполни установку, а не только объясни её.

1. Найди установленный репозиторий: `ZONA_PROJECT_DIR`, соседний файл `installation.json` у установленного навыка или существующая копия ZONA. Если копии нет, клонируй репозиторий в постоянную пользовательскую папку. Не перезаписывай существующую папку и настройки.
2. В корне репозитория выполни `npm ci` (Node.js 18+). Отправка отчётов не требует запуска бота, Ollama, каталога или VPS.
3. Проверь наличие `TELEGRAM_BOT_TOKEN` и `TELEGRAM_OWNER_CHAT_ID` в `.env` ZONA или окружении, не выводя значения. Не подставляй получателя автора репозитория. Если настроек нет, попроси владельца заполнить их локально и отправить своему боту `/start`. Не проси публиковать токен в чате, инструкции или Git. Не перезаписывай другие значения `.env`.
4. Определи клиент и запусти `node scripts/install-reporting.js --client codex|claude|cursor` из репозитория. Установщик добавляет навык и сохраняет существующие инструкции. Для Cursor прочитай созданный `~/.cursor/zona-reporting-user-rule.md` и добавь его через Settings → Rules → User Rules; если интерфейс недоступен, попроси пользователя вставить этот текст. Глобальный навык Cursor сам по себе не гарантирует отчёт в каждом чате. Для текущего проекта можно дополнительно использовать `--project <absolute-path>`: создаётся правило alwaysApply.
5. **В Codex по умолчанию подключай весь путь**, а не только исходящие отчёты: выполни раздел «Полная установка Codex на другом ПК» ниже. Исключение — пользователь явно попросил только исходящие сообщения. Для Claude Code/Cursor или режима только отчётов отправь `node scripts/test-reporting.js` и явно укажи, что обратная передача в этот клиент не подключена.
6. Сообщи, какие клиенты и область настроены, подтверждена ли доставка в обе стороны, что нужно обновить в уже открытых сессиях. Не объявляй полную установку по одному sendMessage, dry-run или SSH-запросу. Не запускай polling на новом ПК и не отправляй тест в группы.

## Полная установка Codex на другом ПК

Подключай новый компьютер к **существующему** приёмнику ZONA на VPS. Не создавай второй приёмник, не переноси каталог/другие проекты и не перевыпускай токен ради нового ПК: это отключит остальные устройства.

1. Проверь доступность инструментов приложения `automation_update`, `send_message_to_thread` и `read_thread`. Найди их через доступный поиск инструментов. Без них не обещай работу обратной связи: сообщи, что нужна среда Codex с этими возможностями. Создание расписания должно выполняться инструментом приложения, не записью TOML вручную.
2. Настрой локальные `.env` и `deploy.local.env`. Для того же владельца используются текущий токен существующего бота, его личный ID, `ZONA_BRIDGE_HOST`, `ZONA_BRIDGE_USER`, `ZONA_BRIDGE_PATH` и **местный** `ZONA_BRIDGE_SSH_KEY`. Эти значения не хранятся в GitHub. Если их нет, спроси путь к локальному файлу настроек или попроси заполнить их локально. Не печатай секреты. Настрой отдельный SSH-ключ этого ПК на сервере через разрешённый доступ; проверь known_hosts. Сохрани остальные параметры файлов.
3. Выполни `node scripts/check-codex-bridge.js --enable`. Команда проверяет Telegram, личного получателя, совпадение настроек с VPS, свежий успешный приём Telegram и очередь. Затем включает мост, не меняя остальные поля `.env`. При ошибке останови зависимые шаги и исправь указанную настройку; не объявляй успех. Если версия серверного протокола старая, обнови только файлы моста с разрешённым доступом, по BRIDGE.md.
4. Используй отдельный ID устройства, который создаёт `deviceId()` в CODEX_HOME или `~/.codex/zona-device-id`. Не копируй его с другого ПК. Получи точные ID текущего чата и хоста из окружения/инструментов приложения; не угадывай по названию проекта.
5. Установщик создал `heartbeat-prompt.txt` рядом с установленным навыком (путь указан в `installation.json`). Прочитай его. Через `automation_update` создай **локальный heartbeat этого ПК**, раз в минуту, в текущем чате, с этим текстом. Сначала проверь существующие автоматизации этого профиля: обнови подходящую вместо создания дубликата. Не меняй автоматизацию другого компьютера. При отсутствии явного запроса не меняй модель. Пустые проверки должны проходить без отчётов и уведомлений.
6. Выполни `node scripts/test-reporting.js --interactive --thread-id <точный-id> --host-id <точный-host>`. Скрипт сохраняет отдельный тестовый отчёт с уникальной меткой и отправляет кнопки рекомендаций и собственной задачи. Попроси владельца нажать тестовую кнопку. Дождись реального сообщения с меткой в **том же** чате, переданного heartbeat; при ручной диагностике используй протокол claim → send_message_to_thread → ack из BRIDGE.md и честно отметь, что проверка была ручной.
7. Проверь также собственный текст: попроси владельца ответить на тестовый отчёт короткой задачей, проверь точное сохранение текста и исходного чата. Только после подтверждённой передачи выполняй ack. Если передача неоднозначна, сначала найди маркер JOB_ID в истории, не отправляй повторно.
8. Заверши установку только с конкретным результатом: исходящий отчёт доставлен, рекомендация возвращена в исходный чат, собственный текст проверен, heartbeat настроен на этом ПК. Если владелец ещё не нажал кнопку/не ответил или среда недоступна, перечисли непроверенные части и сохрани настройку для продолжения. Не выдумывай успех.

Компьютер и Codex должны быть доступны для heartbeat. На остальных ПК повторяются местные настройки и тесты; приёмник VPS остаётся один. Эта процедура не даёт удалённому агенту доступа к другому компьютеру только по ссылке на GitHub.

## После задачи

Пиши от лица девушки ZONA: «я сделала», «проверила». Перед финальным ответом подготовь JSON: `title`, непустые массивы строк `completed`, `checks`, `projectStatus`, `deployment`, `issues`, `nextSteps`. Назови проект и задачу; перечисли выполненное, фактические проверки, известный статус проекта и оставшиеся задачи. Непроверенное помечай; для неприменимого раздела напиши «Не применимо». Для простого вопроса отчёт краткий. Не включай секреты и персональные данные.

В конце содержательного отчёта добавь `recommendations`: до 5 полезных следующих задач, каждая `{ "label": "Короткая кнопка", "prompt": "Полный текст задачи для Codex" }`. Не выдумывай задачи ради кнопок. `report.codex` содержит точный `threadId` и `hostId` исходного чата; отправитель также читает `CODEX_THREAD_ID` из окружения. Никогда не выбирай другой чат по похожему названию. Обратная передача в Claude/Cursor пока не реализована.

При включённом `ZONA_CODEX_BRIDGE=1` отправитель регистрирует отчёт на VPS, прикрепляет кнопки рекомендаций и «Написать свою задачу». Ответ на любую часть отчёта также связывается с исходным чатом. При выключенном мосте рекомендации остаются текстом. Настройка сервера и доставки: [документация моста](https://github.com/divangames/zona/blob/main/BRIDGE.md). Не включай мост до настройки SSH, приёмника и проверки доставки в Codex. Telegram подтверждает постановку в очередь, а не немедленный запуск задачи.

Сохрани JSON с уникальным именем (UUID) вне Git, чтобы параллельные чаты не перезаписывали отчёты. Запусти `node <ZONA>/scripts/send-project-report.js <absolute-report.json> --dry-run`, затем без `--dry-run`. Рабочая папка может быть любой. Не отправляй два отчёта об одном результате из-за нескольких инструкций. Не повторяй весь отчёт автоматически при частичной доставке. При ошибке честно сообщи, что доставка не подтверждена.

Пользовательская просьба включить отчёты служит разрешением на их отправку указанному им владельцу. Если пользователь отменил уведомление в конкретном запросе, не отправляй его. Уже завершённые чужие чаты не перечитывай автоматически и не выдумывай их результаты.
